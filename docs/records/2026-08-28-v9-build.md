## Dowody akceptacji (zmierzone, 2026-08-28)

- Provisioning: 3× `terraform apply -parallelism=1` (4+4+4 create, 0 change/destroy).
- `platform-build`: PASS; sonda platformy — 2 ProxySQL, VIP na `x9p1`, TLS
  endpointu zweryfikowany z hosta aplikacyjnego.
- `cluster-build` **oba tenanty** (Orion i Cassiopeia) z pełną bramką po budowie:
  idempotence, galera, proxysql, endpoint, hardening, app-conformance,
  backup, restore drill, rolling-restart, upgrade-plan, patch, drift, gcache
  (`required 128M < deployed 512M`), pmm-native — wszystkie PASS.
- Backup: `galera-orionv9-r9-20260828-022339` i `galera-cassiopeiav9-r9-20260828-024138`
  off-cluster w S3, AES-256-CBC, sha256 OK; drille na `o9r1`/`c9r1`, wiersze
  zweryfikowane za pierwszym podejściem.
- Health po wszystkich testach: 6/6 węzłów Galery `Primary / size=3 / Synced(4) / Ready ON`.
- Failover writera (chaos-failover, SIGKILL mariadbd): Orion gap **6.2 s**,
  Cassiopeia **6.4 s**, 550/549 transakcji — **0 utraconych**.
- Failover ProxySQL VIP (stop keepalived na posiadaczu, workload przez VIP):
  oba tenanty wznowione, **0 utraconych transakcji**; po testach VIP wrócił na `x9p1`.
- Benchmark (metodologia v8 niemożliwa 1:1 — `mariadb-slap` 11.4 ma wyścig w
  `--create-schema`, ~50% biegów `No database selected`; write liczone slapem,
  read własną pętlą process-per-query, więc wartości read nie są porównywalne
  z v8 liczonymi persistent-connection):

    VIP Cassiopeia **0.979 s** (~4086 q/s), direct socket **0.769 s** (~5201 q/s)
    — spójne z v8 (VIP insert 4357 q/s, direct 5089 q/s),

    nie bezwzględne q/s.
